# 🎮 2Dローグライク制作 プロトタイプ基本仕様書＆開発設計書

## 1. 概要・プロジェクト目的
* **目的**: 就職活動における「学生時代力を入れたこと（ガクチカ）」およびポートフォリオの制作。完全な製品版ではなく、最低限ゲームとしての体裁（コアプレイ）を保ちつつ、技術力と設計力をアピールする。
* **ゲームジャンル**: 見下ろし2Dローグライク・アクションシューティング。
* **コンセプト**: **「リアルタイムのハイスピードアクション（WP・ポーズなし）」** と **「時間停止中の戦略的コマンド選択」** の融合。
* **ターゲット・評価ポイント**: 
  * 明確なコンセプト設計と独自システム（WP・ブレイク・ゾーン）の実装力。
  * Unity 6環境での保守性・拡張性の高いデータ設計（ScriptableObject/ビットフラグ等）。

---

## 2. 開発環境・システムアーキテクチャ

* **ゲームエンジン**: Unity 6（New Input System ＋ Rigidbody2D物理移動）。
* **コードエディタ / バージョン管理**: VS Code / GitHub（Issueベースでのタスク管理・機能別ブランチ運用）。
* **基本操作仕様**:
  * **WASD**: 移動（斜め移動補正あり）。プレイヤーは常に画面中央にカメラ追従。
  * **マウス / 右スティック（RT/LT等）**: スキル発動・照準。
  * **コマンドウィンドウ起動ボタン**: 時間停止（ポーズ）/ スロウモード切替。

## 3. 戦闘・アクションシステム仕様

### ① WP（ウェポンゲージ）とスキル攻撃
* **通常攻撃の廃止**: 専用の「通常攻撃ボタン」は存在せず、各ボタン（RT, LT等）に割り当てたスキルを消費WPを払って発動する（FFXIII-LR風）。
* **WP管理と裏武器の高速回復**:
  * 武器ごとに独立した**WP**...ATBゲージを持つ。
  * 武器は最大3本（または2本）所持でき、ワンボタン（LR等）で自由に即時切替可能。
  * **現在手にしていない「裏の武器」はWPが通常よりも早く回復**するため、タイミング良く武器を持ち替えながら戦うのが基本戦略となる。

### ② ブレイクシステム（BP）
* **BP（Break Point）**: 敵に攻撃を当てることで蓄積。一定量に達すると敵は**ブレイク状態**（移動不能・デバフ付与）に陥る。
* **ダメージ倍率アップ**: ブレイク中の敵に対して攻撃をヒットさせるとダメージ倍率が上昇する（ボス敵に対しても有効）。
* **BPの減少**: 時間経過で減少するが、敵の種類ごとに上がりやすさ（耐性）や減少速度が異なる。

### ③ コマンド・アイテムウィンドウ（CW）
* **3段階トグル制御**: 起動ボタンを押すことで、**「武器スキル」モード ➔ 「アイテム欄」モード ➔ 「閉じる（通常画面）」** と状態が遷移する。
* **世界停止 ＋ 背景モノクロ化**: CW表示中はワールド全体（敵・プレイヤー・弾）の動きが停止し、画面にモノクロフィルターが適用される。
* **全スキル選択＆ショートカットバインド**:
  * ボタンに割り振っていないスキルも、CWのコマンド一覧から直接選択・発動が可能。
  * CW表示中にフォーカスしたスキル上で Fire1 / Fire2 ボタンを押すと、そのスキルを即座に現在の武器のショートカットキーへ上書き登録できる。

### ④ リソース管理まとめ
| リソース | 消費用途 | 回復・蓄積手段 |
| :--- | :--- | :--- |
| **ST（スタミナ）** | ダッシュ、ブリンク（回避行動） | 時間経過（早めの回復） |
| **WP（ウェポンゲージ）** | スキル発動（武器ごとに固有） | 時間経過（裏武器は高速回復） |
| **SP（スペシャルポイント）** | 大技や特殊行動 | 攻撃ヒット、敵攻撃に対するジャスト回避 |

## 4. キャラクター成長・ステータス設計

* **敵味方共通コンポーネント（`EntityStats.cs`）**:
  * プレイヤー・敵ともに同一のステータス計算・ゲージ管理システム（`ResourceGauge`）を利用する。
* **基礎ステータス（6項目 / レベル0〜9）**:
  * **ATK / INT / DEF / MND / VIT / DEX** の整数レベルで構成。
  * **HP** は VIT に依存、**ST** は DEX に依存して最大値がスケール計算される。
* **状態異常管理（`StatusEffectManager.cs`）**:
  * 単一責任の原則に従い、ステータス本体から分離して独立したコンポーネントとして管理。
  * 炎上、浸水、氷結、麻痺、脆弱などの継続効果・バフデバフを担当。
* **インゲーム成長と清算**:
  * **武器レベル**: 敵撃破時に経験値が蓄積され、戦闘中であってもリアルタイムにレベルアップ・スキル解放が反映される。
  * **プレイヤーEXP**: 敵撃破時に手に入るプレイヤー用EXPは、ダンジョン内の**休憩所**でのみ清算・基本ステータス強化へ消費可能。

## 5. ダンジョン構造・ローグライク設計

* **1プレイのスコープ**:
  * **0階層（チュートリアル）**: 最大10分程度で基本操作・システムを網羅。
  * **1〜3階層（本編）**: 各階層に部屋巡回（ショップ/休憩所点在）＋ 中ボス×2 ＋ 大ボス×1（所要時間：約20分）。
* **動的生成・描画制御（動的インサイト生成）**:
  * 画面上には**現在プレイヤーがいる部屋のみ**を生成（Instantiate）し、退場時に破棄（Destroy）することで処理を最適化。
* **部屋タイプ（ビットフラグ管理 / `RoomType`）**:
  * `[System.Flags]` を使用し、「敵出現」「宝箱」「ショップ」「休憩所」「ボス」などの属性を複数重複して持たせる設計（例：敵が出現し、かつ宝箱もある部屋）。
* **ウェーブ形式の部屋ロック**:
  * 敵が出現する部屋では退路が遮断（ドアロック）され、敵が複数ウェーブでスポーンする。全滅させるとロックが解除される。
* **宝箱の距離判定解錠**:
  * 宝箱の一定距離内に敵が存在する場合ロックがかかり、周辺の敵を排除することで自動解錠される。

## 6. 周回・永続要素（メタプログレッション）

* **リセットされる要素（敗北時）**:
  * ダンジョン内で上昇させたプレイヤーレベル・基礎ステータス。
  * ダンジョン内で上昇させた武器レベル。
* **引き継がれる要素（永続保持）**:
  * 獲得・解放した**武器（アーティファクト）本体**。
  * 武器を使って敵を倒した際などに解放された**特有の「アビリティ・スキル」**。
